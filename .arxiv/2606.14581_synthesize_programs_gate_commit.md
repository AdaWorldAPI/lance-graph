# CARE — Synthesize Programs, Gate Commit

**Paper:** *CARE: Context-Aware Ranking Evolution with Executable Scoring Programs for Budgeted Reaction Optimization*  
**Authors:** Guanyu Liu, Weiyi Kong, Chao Tang, Zeyu Wang, Boer Zhang, Baiqing Li, Peiyu Zhang, Tianyu Shi  
**arXiv:** 2606.14581v5  
**Source:** https://arxiv.org/abs/2606.14581  
**Date:** 2026-08-31

## Punchline

> **Let the model synthesize a reusable decision program; make deterministic machinery validate, replay, compare, and commit it.**

CARE's transferable result is not "use an LLM for chemistry."

It is a control split:

```text
revealed evidence
      |
      +------------------------------+
      |                              |
      v                              v
deterministic reference       synthesized scoring program
      |                              |
      |                       validate + replay
      |                              |
      +---------- compare -----------+
                     |
                     v
                 commit gate
                     |
               decision record
              ===== RUBICON =====
                     |
                 outcome reveal
                     |
                next state
```

The generated program is allowed to **propose a ranking rule**. It is not allowed to silently become the actuator.

For lance-graph this is a strong architectural prior for `0..63 × R2IL × fold/mask × Rubikon`: cognition can be synthesized occasionally, compiled into a tiny replayable program, and then executed without an LLM in the hot path.

# What the paper actually establishes

## 1. Program synthesis is separated from action selection

CARE does not ask the LLM for the next experiment.

The LLM produces an executable scoring program `pi_t` that assigns a finite score to every remaining candidate. Its maximum becomes an initial proposal. A non-LLM reference policy independently produces the default candidate.

The final action is chosen later by a reference-conditioned gate.

That gives three different objects:

```text
program logic
candidate proposal
committed action
```

They are deliberately not the same thing.

### Substrate takeaway

Do not let a synthesized `0..63` recipe imply its own authority.

A generated recipe may say:

```text
filter -> project -> fold -> rank
```

but the runtime still decides whether that recipe may displace the current deterministic reference path.

---

## 2. The executable program is a persistent artifact

A direct LLM answer disappears into the trajectory.

CARE instead stores runnable scoring logic that can be:

- reused;
- revised;
- regenerated;
- validated;
- compared with previous programs;
- replayed on revealed history;
- audited after the fact.

The important representation shift is:

```text
"choose candidate X"
        ->
"here is the rule that ranks the whole current candidate population"
```

### Substrate takeaway

Treat reasoning as an **artifact with identity**, not a transient sentence.

Candidate mapping:

```text
semantic evidence
      |
      v
R2IL / 0..63 microprogram
      |
      +-- program hash / identity
      +-- required inputs
      +-- allowed primitives
      +-- produced ranking / terminal
      +-- validation result
      +-- replay score
```

The LLM may disappear after compilation. The artifact remains executable.

---

## 3. Program validation is semantic, not merely syntactic

CARE requires a candidate program to pass:

- compilation;
- restricted execution;
- complete finite scoring;
- invariance to candidate order.

If validation fails, the controller falls back to the reference policy.

Candidate-order invariance is especially valuable:

> Reordering physical storage must not alter semantic ranking.

### Substrate takeaway

For lance-graph, this should become a general contract:

```text
permute(storage/layout)
        ->
same semantic state
        ->
same scores
same ranking
same committed ordinal
```

This catches accidental intelligence leaking from:

- row order;
- chunk boundaries;
- ordinal allocation;
- hash iteration;
- SIMD lane position;
- candidate enumeration order.

---

## 4. The reference path is not a fallback after failure; it is a first-class peer

CARE always constructs a numerical reference candidate and support summary.

The generated program is therefore evaluated as a **challenger to an already valid decision**, not as the sole decision-maker.

This is stronger than:

```text
try LLM
if crash -> fallback
```

It is:

```text
reference = valid default
alternative = optional challenger
gate(reference, alternative) -> commit
```

### Substrate takeaway

The deterministic substrate should remain capable before any adaptive/synthesized layer is added.

Possible split:

```text
reference:
    hydrated ontology
    + observed statistics
    + fixed causal / evidential rules
    + deterministic folds

challenger:
    newly synthesized orchestration
    over the same permitted evidence

commit:
    explicit evidence comparison
```

Adaptive reasoning augments the substrate instead of replacing its floor.

---

## 5. The gate is a separate decision algebra

CARE forms an alternative and computes a comparison score from positive and penalty features.

Only an eligible alternative whose comparison clears the gate may replace the reference.

The paper's implementation uses evidence such as:

- refinement score;
- reference score margin;
- combined score margin;
- ranker agreement;
- aggregate rank;
- novelty;
- categorical support;
- exploration support;

and penalties for disagreement with strongly supported references or weak independent support.

The exact coefficients are chemistry/controller-specific.

The transferable structure is not those numbers. It is:

```text
proposal quality
+ independent support
+ disagreement
+ novelty
+ reference strength
        ->
explicit commit decision
```

### Substrate takeaway

This resembles the intended role of a compact reasoning band much more than "confidence = action."

Evidence can accumulate through folds, palette statistics, ontology agreement/disagreement, missing-link state, and causal grade, while the final commit remains a distinct operation.

---

## 6. Pre-outcome and post-outcome state are explicitly separated

CARE records the selection before the selected outcome is revealed.

Its trace distinguishes:

```text
PRE
    program
    reference
    alternative
    gate features
    gate score
    committed candidate
============================== RUBICON
POST
    revealed outcome
    best-so-far update
    controller update
```

The post-outcome update affects only later decisions.

### Substrate takeaway

This is almost exactly the replay boundary lance-graph needs:

> **Nothing learned after a commit may retroactively alter the evidence or program that produced that commit.**

A replay record should therefore contain enough pre-Rubicon state to reproduce the selection bit-for-bit.

---

## 7. Learning can occur by program replacement rather than weight updates

Each newly revealed outcome may cause the active program to be:

```text
retain
revise
regenerate
```

No LLM parameter update is required.

This is a useful form of learning for a deterministic substrate:

```text
experience
   ->
change which executable reasoning program is active
   !=
mutate opaque model weights
```

### Substrate takeaway

A `0..63` schedule can be learned as an executable orchestration object.

The learner's job becomes:

```text
discover / compile / validate / select recipe
```

rather than:

```text
continuously perturb runtime semantics
```

---

## 8. Old validated programs may become active again

CARE does not assume the newest program is the best one.

The reported controller chooses among:

- the newly produced artifact;
- up to four recent validated artifacts;
- the first validated artifact;

using **revealed-only prequential replay**.

A previous program can therefore be resurrected when its revealed-history score becomes superior.

### Substrate takeaway

Program revision should not mean destructive replacement.

Maintain a tiny content-addressed program portfolio:

```text
P0 P1 P2 P3 P4
 |  |  |  |  |
 +-- revealed-only replay --+
             |
             v
         active program
```

This gives deterministic rollback as part of learning.

---

## 9. Replay must hide future outcomes

The prequential selector evaluates programs on prefixes of revealed history and scores their ranking against later members of the **already revealed** trace.

Future fold outcomes are withheld while the ranking is computed.

This prevents the offline evaluator from quietly leaking future information into the selected program.

### Substrate takeaway

For any adaptive reasoning benchmark:

```text
decision_t may consume evidence <= t
decision_t must not consume evidence > t
```

The rule sounds obvious. It deserves a hard test because caching, hydrated graphs, precomputed statistics, and full-population folds can violate it accidentally.

---

## 10. Direct program control is an important negative control

The paper explicitly compares CARE with a controller in which the evolving scorer selects directly.

The hybrid reference + alternative + gate architecture is stronger.

Component ablations also show degradation when the intervention gate, planner adaptation, or refinement mechanisms are removed.

This matters more than the raw chemistry score.

It supports the architectural hypothesis:

> **Adaptive symbolic logic is more useful as a constrained challenger than as an unreviewed actuator.**

# Harvest for lance-graph

## H1 — LLM as compiler, not runtime

The preferred hot path is:

```text
LLM / search / synthesis
        |
        v
validated R2IL / 0..63 artifact
        |
        v
deterministic mask / fold / route
        |
        v
gate
        |
        v
commit
```

Once the artifact exists, ordinary execution must not need the LLM.

This is the strongest harvest from CARE.

---

## H2 — A reasoning recipe must rank a population, not name one answer

A recipe should expose how it evaluates the full eligible population.

Bad interface:

```text
reason(state) -> candidate_id
```

Preferred interface:

```text
score(program, state, population) -> ordered population
commit(reference, challenger, evidence) -> selected ordinal
```

This makes the reasoning inspectable and testable.

---

## H3 — Reference and challenger should share evidence, not authority

The same hydrated substrate may feed both paths:

```text
V_t
 |
 +--> fixed/reference orchestration
 |
 +--> synthesized/challenger orchestration
```

The challenger gets no hidden channel and no privileged state.

Only the explicit gate grants authority.

---

## H4 — Rubicon should be a storage boundary

Commit enough state before outcome reveal to make the decision independently replayable:

```text
program id/hash
program inputs or content-addressed view
reference candidate + support
challenger candidate + support
gate inputs
gate result
selected ordinal
decision-time substrate generation
```

After this record exists, later learning may append but never rewrite it.

---

## H5 — Program identity belongs beside data identity

If substrate state is content-addressable but reasoning logic is not, replay remains incomplete.

Treat the microprogram as another immutable input:

```text
decision =
F(
  substrate_generation,
  evidence_view,
  program_hash,
  gate_version
)
```

A replay must pin all four.

---

## H6 — Program evolution should be sparse

CARE calls the expensive synthesizer to change a reusable rule rather than asking it to make every primitive decision.

For lance-graph this suggests:

```text
many cheap deterministic executions
        per
rare expensive program synthesis
```

That fits the goal of making intelligence live in the orchestration of a small primitive ISA rather than in repeated model inference.

---

## H7 — Do not copy CARE's gate coefficients

The paper's weights and thresholds are implementation choices for its chemistry benchmarks.

Do **not** transplant them into the substrate.

Harvest only the decomposition:

```text
eligibility
support
comparison
penalty
commit threshold
```

Our gate should derive from substrate-native evidence and causal contracts.

---

# Testables / falsifiers

## T0 — Candidate-order invariance

Build one semantic candidate population and evaluate it under many physical permutations.

```text
P
shuffle(P)
chunk(P)
reverse(P)
different insertion order
```

**Pass**

```text
score(candidate) identical
ranking identical
reference ordinal identical
challenger ordinal identical
commit identical
```

after mapping physical rows back to semantic candidate identity.

**Fail**

Any decision depends on storage order.

This should be a foundational property test.

---

## T1 — LLM-free replay

Synthesize and validate one reasoning program once.

Persist the artifact.

Then remove all LLM access and replay the same decision state.

**Pass**

```text
same program execution
same ranking
same gate inputs
same committed ordinal
```

bit-for-bit.

**Fail**

Execution still depends on hidden natural-language/model state.

This is the primary falsifier for "LLM as compiler."

---

## T2 — Pre/post Rubicon isolation

Record a decision at time `t`.

Then vary the subsequently revealed outcome over several possible values while keeping all pre-decision state fixed.

**Pass**

The already committed action and its trace remain identical.

Only `state_{t+1}` and later decisions may differ.

**Fail**

Post-outcome information mutates the completed decision.

---

## T3 — Future-leakage test

Create a replay with history:

```text
H0, y1, y2, ... yn
```

At decision `t`, poison every outcome `y[k]` for `k > t`.

**Pass**

Decision `t` is unchanged.

**Fail**

Any precomputed statistic, hydrated field, fold, cache, or selector consumed future evidence.

Run this against every adaptive selector.

---

## T4 — Challenger cannot self-authorize

Construct a synthesized program that gives one candidate an extreme score.

Give the reference strong contradictory evidence.

**Pass**

The program can change its own ranking but cannot bypass gate eligibility or force commit.

**Fail**

Score magnitude leaks into authority without an explicit comparison path.

---

## T5 — Invalid-program fallback

Generate artifacts that independently violate:

1. compile validity;
2. restricted primitive set;
3. finite scoring;
4. complete population scoring;
5. candidate-order invariance.

**Pass**

Each invalid artifact is rejected before selection and the reference path remains valid.

**Fail**

Malformed generated logic can corrupt or partially control the selection path.

---

## T6 — Reference / direct / gated triad

For the same task and replay seeds compare:

```text
A = deterministic reference only
B = synthesized program selects directly
C = deterministic reference + synthesized challenger + gate
```

Measure:

- terminal quality;
- best-so-far AUC;
- failure/catastrophic-choice rate;
- replay determinism;
- number of challenger interventions.

**Target**

`C` should outperform or Pareto-dominate `B`.

If direct synthesis consistently dominates the gated design under matched information and cost, the CARE-inspired architecture is not earning its complexity.

---

## T7 — Program resurrection

Create a trajectory in which:

```text
P0 good early
P1 better for a short local regime
P2 overfits recent evidence
P0 best again on revealed-only prequential replay
```

**Pass**

The selector can reactivate `P0` without regenerating or mutating it.

**Fail**

"learning" is forced to follow artifact recency rather than measured replay performance.

---

## T8 — Revision is non-destructive

Revise program `P0 -> P1`.

**Pass**

- `P0` hash and bytes remain unchanged;
- historical decisions referencing `P0` still replay;
- `P1` receives a new identity;
- both may coexist in the validated portfolio.

**Fail**

Revision overwrites the artifact needed by old traces.

---

## T9 — Program compression equivalence

Start with a richer generated scorer `S`.

Compile it into the intended substrate representation `R` such as an R2IL / `0..63` recipe.

For a large randomized set of admissible states:

```text
rank_S(V) == rank_R(V)
```

and, with the same reference path:

```text
commit_S(V) == commit_R(V)
```

**Pass**

The compact program preserves semantic behavior.

**Fail**

The ISA is missing a primitive or the compiler changes the decision surface.

This directly tests whether free-form reasoning can crystallize into deterministic substrate orchestration.

---

## T10 — Layout and execution-plan invariance

Execute the same validated recipe through semantically equivalent physical plans:

```text
fold directly
mask -> fold
different chunk widths
different SIMD lane grouping
equivalent destination binding
parallel vs serial reduction
```

where the algebra permits equivalence.

**Pass**

Same semantic ranking and commit.

**Fail**

Physical execution shape leaks into reasoning semantics.

---

## T11 — Reference strength monotonicity

Hold the challenger fixed.

Increase independent support for the reference while leaving challenger evidence unchanged.

**Pass**

The challenger must not become *easier* to commit merely because reference support grew.

The exact gate need not be linear, but basic monotonicity should hold for evidence explicitly defined as reference support.

**Fail**

Comparison algebra has a sign/routing bug.

---

## T12 — Challenger support monotonicity

Hold the reference fixed.

Increase independent, admissible support for the same challenger without changing contradictory evidence.

**Pass**

The challenger must not become less eligible solely because genuine supporting evidence increased.

**Fail**

Support aggregation or normalization is misrouted.

---

## T13 — Decision trace sufficiency

Persist only the declared decision record and immutable referenced artifacts.

Restart from a clean process with caches empty.

**Pass**

The selected ordinal and all gate diagnostics can be reconstructed.

**Fail**

The supposedly replayable decision depended on undeclared ambient state.

---

# Minimal executable contract

A CARE-shaped substrate contract could be no larger than:

```rust
trait ReasoningProgram {
    fn score(
        &self,
        view: &DecisionView,
        candidate: Ordinal,
    ) -> FiniteScore;
}

struct DecisionRecord {
    substrate_generation: Generation,
    program_hash: ProgramHash,

    reference: Ordinal,
    challenger: Option<Ordinal>,

    gate_version: GateVersion,
    selected: Ordinal,
}
```

The important properties are more important than these types:

```text
complete scoring
finite scoring
order invariance
immutable program identity
pre-outcome commit
explicit authority gate
LLM-free replay
```

Do not add a new runtime abstraction merely because CARE uses Python-like scoring programs. Bind this onto existing fold/mask/route machinery if the current primitives already express it.

---

# Suggested implementation order

## P0 — prove replay purity first

Implement only enough fixture machinery for:

- `T0` candidate-order invariance;
- `T1` LLM-free replay;
- `T2` Rubicon isolation;
- `T3` future-leakage.

No model integration is required.

## P1 — immutable microprogram identity

Pin a reasoning artifact by hash/version and put that identity into a decision trace.

Prove `T8` and `T13`.

## P2 — reference/challenger gate

Use existing substrate evidence only.

Prove `T4`, `T11`, and `T12`.

## P3 — program portfolio

Keep a tiny bounded set of immutable validated programs and select among them by revealed-only replay.

Prove `T7`.

## P4 — compiler experiment

Only now ask whether a free-form generated scorer can compile into existing R2IL / `0..63` orchestration without semantic loss.

Prove `T9`.

If it cannot, identify the missing algebra before inventing another execution layer.

---

# Kill criteria

This paper should **not** justify an implementation arc if any of these are true:

1. Existing deterministic orchestration cannot be replayed independently of ambient state.
2. Candidate order or physical layout changes the semantic decision.
3. The generated program must remain attached to an LLM at execution time.
4. The challenger can bypass an explicit authority/commit boundary.
5. Historical decisions cannot pin the exact program and substrate generation that produced them.
6. A direct generated selector consistently beats the gated architecture under matched information, budget, and safety constraints.
7. Compiling the useful generated scorers into the existing ISA requires so many special cases that the "small deterministic instruction set" hypothesis stops being credible.

These are useful failures. They tell us which layer is actually missing.

---

# What not to import

Do not import CARE's chemistry-specific:

- ranker ensemble;
- fixed gate coefficients;
- refinement thresholds;
- exploration formulas;
- prompt schema;
- Python execution environment.

Do import its separation of concerns:

```text
synthesize
validate
rank
compare
commit
record
reveal
revise
```

That sequence is the real contribution for the substrate.

---

# One-line architecture law

> **Generated reasoning may propose a deterministic program; only replayable evidence may grant that program authority to commit.**
