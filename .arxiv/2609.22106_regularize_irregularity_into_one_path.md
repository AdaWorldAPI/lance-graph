# PRQuant — Regularize Irregularity Into One Path

**Paper:** *PRQuant: Permutation Residual Quantization for Low-Overhead Inference*  
**arXiv:** 2609.22106  
**Source:** https://arxiv.org/abs/2609.22106  
**Date:** 2026-08-16

## Punchline

> **Detect sparse irregularity, compile it into regular coordinates, then widen the existing primitive instead of introducing a second runtime path.**

PRQuant is useful to lance-graph less as a quantization recipe than as an execution-layout result.

A small set of difficult channels dominates quantization error. PRQuant identifies those channels after AWQ-style scaling, permutes them into contiguous tail blocks, computes their weight residuals offline, and executes the correction as part of one regular tail-augmented low-precision GEMM.

The key separation is:

```text
logical meaning
    !=
physical execution layout
```

Permutation primarily regularizes access. Residual compensation carries most of the numerical correction.

---

## What the paper actually establishes

### 1. Sparse difficulty can be physically regularized

Problematic channels need not remain scattered.

```text
scattered hard coordinates
        |
        v
offline permutation
        |
        v
contiguous tail
```

This removes dynamic gather-style irregularity from the inference path.

### 2. Residual correction does not require a second runtime operator

For a selected tail, PRQuant constructs the weight residual offline:

```text
R_W = W_tail - Q(W_tail)
```

The ordinary and residual dimensions are then consumed by one augmented GEMM rather than a normal GEMM plus a separate correction kernel.

### 3. Permutation and numerical correction are different jobs

The ablations matter:

- smoothing/scaling and residual compensation provide the main reconstruction improvement;
- permutation has smaller direct numerical effect;
- permutation's larger role is to make the correction contiguous and hardware-friendly.

Therefore:

> **Do not confuse a useful physical coordinate transform with a new semantic operator.**

### 4. Regular width can be cheaper than irregular execution

PRQuant spends additional reduction width on the residual tail in exchange for avoiding scattered gathers and a separate residual path.

This suggests a general systems trade:

```text
cheap regular width
    >
expensive irregularity
```

when the added width remains bounded.

### 5. The pattern is broader than permutation

The paper explicitly discusses the same offline-absorption principle for channel transforms such as scaling, block permutation, channel duplication, structured augmentation, and related transformations that can be absorbed into neighboring operators.

# Harvest for lance-graph

## H1 — Fixed semantic ISA, plastic physical geometry

Do **not** permute the meaning of cognitive ordinals.

For a logical reasoning ISA such as `0..63`:

```text
logical ordinal                  physical execution ordinal

0..63 stable semantics   --->    compiled / calibrated layout
replay contract                  free to reorder physically
```

The semantics remain replayable. The execution geometry may change.

This is the strongest substrate takeaway from PRQuant.

---

## H2 — Permutation belongs in lowering/binding, not reasoning

Treat rotation, permutation, destination binding, or coordinate changes as compilation when they preserve semantics.

```text
semantic coordinates
        |
        v
bind / lower / permute
        |
        v
regular physical coordinates
        |
        v
existing Local / Via / fold
```

This is consistent with the existing architecture rule:

> Do not search for a new fold primitive until the desired destination has been proven impossible to bind to an existing ordinal/path.

---

## H3 — Residual Tail Principle

For a sparse set of difficult coordinates:

1. detect them offline or at a replay/calibration boundary;
2. preserve their logical identities;
3. bind them to a contiguous physical region;
4. attach the required corrective representation;
5. widen the existing reduction/fold domain;
6. avoid a second runtime path unless the correction cannot be represented in the existing algebra.

Candidate conceptual shape:

```rust
struct CompiledLayout {
    logical_to_physical: Permutation,
    regular_len: u16,
    residual_tail: Range<u16>,
}
```

This is a hypothesis, not an implementation prescription. The metadata may belong entirely in lowering and need not become persistent DTO state.

---

## H4 — Local plasticity may alter execution geometry without altering semantics

A Moore/local-plasticity layer should not need to mutate the meaning of an operator.

Instead:

```text
local prediction / reconstruction error
                |
                v
identify difficult coordinates
                |
                v
rebind / repack physical layout
                |
                v
allocate bounded residual capacity
                |
                v
same execution primitive
```

Possible lance-graph hardness signals include:

- prediction miss;
- agreement/disagreement;
- calibrated Fisher-Z evidence;
- Shannon entropy;
- revision conflict;
- causal inconsistency;
- repeated epistemic-hole activation.

The claim to test is not that PRQuant proves such plasticity.

The transferable hypothesis is:

> **Experience may improve future execution by changing physical layout/capacity while leaving the logical ISA invariant.**

---

## H5 — No-second-path is a testable optimization rule

Prefer:

```text
compile exception structure
        |
        v
one widened fold
        |
        v
terminal
```

over:

```text
mask / gather
    |
materialize
    |
normal fold
    |
special correction traversal
    |
merge
```

But this is not dogma. If the widened path loses on measured latency, bytes touched, cache behavior, or determinism, reject it.

# Testables / falsifiers

## P0 — Semantic invariance

**Question:** Can physical layout change without changing logical results?

Run the same logical program with:

- canonical physical layout;
- one or more arbitrary bijective permutations.

**Pass**

```text
terminal(canonical) == terminal(permuted)
```

bit-for-bit wherever the integer/fixed-point contract permits it.

**Fail means:** physical layout leaked into semantics. That is an architecture defect, not a tuning issue.

---

## P1 — Widened fold equivalence

Compare:

```text
normal fold + separate correction
```

against:

```text
single widened fold [normal | residual]
```

**Pass:** identical terminal result.

**Fail means:** the correction is not closed under the existing fold algebra and must not be smuggled into it.

---

## P2 — No-materialization test

Compare a path that materializes an intermediate mask/population with one that resolves the equivalent binding during lowering.

Measure:

- terminal equality;
- bytes read;
- bytes written;
- allocations;
- latency.

**Pass:** same terminal, fewer writes/reads or lower latency.

**Fail means:** binding has not bought enough to justify the added compiler/layout machinery.

---

## P3 — Gather versus contiguous-tail benchmark

Select 8/16/32 difficult ordinals.

Compare:

- scattered physical positions requiring gather/indirection;
- the same logical ordinals packed into a contiguous tail.

Measure:

- load count;
- cache misses if available;
- cycles/op;
- fold throughput.

**Pass:** contiguous layout wins materially.

**Fail means:** the PRQuant physical-layout lesson does not transfer to this execution target.

---

## P4 — Residual-width sweep

Sweep bounded extra capacity:

```text
k = 0, 2, 4, 8, 16, 32 ...
```

Measure error reduction versus:

- execution width;
- latency;
- bytes touched.

**Expected:** a Pareto knee where small extra width removes a disproportionate fraction of error.

**Fail means:** difficulty is not sparse/concentrated enough for a residual-tail architecture.

---

## P5 — Hardness concentration

Measure error contribution per logical coordinate/operator.

Candidate error signals:

- prediction miss;
- revision conflict;
- entropy;
- calibrated disagreement;
- causal inconsistency.

Sort by contribution and plot cumulative error explained.

**Expected:** a small fraction of coordinates explains a large fraction of total error.

**Fail means:** there is no PRQuant-like outlier structure to harvest.

---

## P6 — Tail stability

Choose the hard tail from calibration batch A.

Evaluate hardness ranking on independent batches B/C.

Measure:

- top-k overlap;
- rank correlation;
- retained error coverage.

**Pass:** useful stability over the intended calibration/replay interval.

**Fail means:** offline layout becomes stale too quickly and would require a dynamic path that may erase the benefit.

---

## P7 — Plastic layout, immutable ISA

Allow a local/Moore calibration mechanism to change only:

- logical-to-physical mapping;
- residual-tail membership;
- bounded residual capacity.

Do **not** allow it to redefine logical operator semantics.

Replay historical traces before and after recalibration.

**Pass:**

- historical logical traces remain equivalent;
- terminal replay remains invariant;
- holdout execution/error improves.

**Fail means:** plasticity has contaminated deterministic semantics.

---

## P8 — Structural ablation

Benchmark four variants:

1. baseline;
2. + permutation only;
3. + residual capacity only;
4. + permutation + residual capacity.

Separate:

- semantic/error improvement;
- execution/layout improvement.

**Expected PRQuant-like pattern:**

- residual capacity carries most error reduction;
- permutation alone carries little semantic gain;
- permutation materially improves the execution cost of residual handling.

**Fail means:** either the analogy does not transfer or permutation is doing something semantically meaningful in this substrate and must be modeled differently.

---

## P9 — One-path supremacy

Compare:

```text
widened one-pass fold
```

with:

```text
base fold + residual pass + merge
```

for identical results.

Measure:

- ns/op;
- loads/stores;
- bytes touched;
- branch/gather overhead;
- materializations.

**Pass:** widened fold is equal or better on the relevant cost surface.

**Fail means:** "no second path" is not an optimization law for this hardware/workload.

Keep the two-path implementation if it wins.

---

## P10 — Replay after recompilation

1. execute and record a logical trace under physical layout A;
2. recalibrate to physical layout B;
3. replay the same logical trace.

**Pass:**

```text
logical trace A == logical trace B
terminal A      == terminal B
```

Physical addresses may differ.

**Fail means:** execution layout has accidentally become part of epistemic history.

---

## P11 — Error-driven remapping predicts future utility

Use batch A to select hard coordinates from an explicit error signal.

Repack only the top-k.

Evaluate on unseen batch B.

**Pass:** error-driven remapping improves B.

**Fail means:** the chosen hardness signal is descriptive but not predictive.

---

## P12 — Random-tail control

For the same `k`, compare:

- hardness-selected residual tail;
- random residual tail;
- optionally frequency-selected tail.

Keep total capacity exactly equal.

**Pass:**

```text
hardness-selected > random
```

on unseen data.

This is the cleanest first falsifier for local plasticity.

If extra width alone explains the gain, the adaptive-layout story is false.

---

# First experimental cut

Do not build a new subsystem first.

The smallest useful sequence is:

```text
P0  semantic invariance
 |
P1  widened-fold equivalence
 |
P4  residual-width Pareto sweep
 |
P12 learned-tail versus random-tail
```

These four tests answer most of the architectural question.

### Continue only if all four survive

Then test:

```text
P5 hardness concentration
P6 tail stability
P7 plastic-layout replay
P9 one-path performance
P10 recompilation replay
P11 holdout prediction
```

# Architecture guardrail

The reusable rule is:

> **When a small irregular subset appears expensive, first ask whether its logical identity can remain fixed while its physical coordinates are compiled into a regular region consumed by an existing primitive.**

Only add a new runtime operator if that transformation is impossible or loses empirically.

In compact form:

```text
fixed semantic ISA
        x
learnable / compiled physical layout
        x
regular widened algebra
```

Or, more brutally:

> **The ISA does not learn. Its execution geometry may.**

That is the part of PRQuant worth trying to falsify in lance-graph.
