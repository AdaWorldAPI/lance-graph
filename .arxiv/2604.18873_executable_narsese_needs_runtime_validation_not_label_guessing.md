# Gabriel & Wang 2026 — Executable Narsese must be validated, not guessed from labels

**Paper:** Mina Gabriel, Pei Wang, *From Natural Language to Executable Narsese: A Neuro-Symbolic Benchmark and Pipeline for Reasoning with NARS*, arXiv 2604.18873v1, April 2026.  
**arXiv:** https://arxiv.org/abs/2604.18873  
**PDF:** https://arxiv.org/pdf/2604.18873  
**Dataset:** https://huggingface.co/datasets/MinaGabriel/NARS-Reasoning-v0.1  
**Engine:** https://github.com/opennars/OpenNARS-for-Applications  
**Read:** 2026-10-11.

## Punchline

> **A correct natural-language label is not enough. Compile the input into executable symbolic structure, run that structure in a reasoner under a fixed protocol, and report both answer accuracy and execution success.**

## Exact benchmark facts (§4, §6)

- 1,000 retained natural-language reasoning instances.
- Derived from ProverQA/ProverGen-style FOL reasoning tasks.
- Each pairs context, query, gold label, FOL form, and ONA-executable Narsese.
- Gold labels: `True`, `False`, `Uncertain`.
- Easy: **400**, 1–2 reasoning steps; medium: **300**, 3–5; hard: **300**, 6–9.
- Official split: **800 train** (300/250/250 easy/medium/hard), **200 test** (100/50/50).
- **These depths are NOT NAL-1..NAL-9 levels.** They measure inference-chain length within this dataset.
- The dataset was *filtered* to retain instances whose executable Narsese matches the inherited gold label under ONA. This can cause selection bias relative to unrestricted FOL programs.

### The executable protocol is part of the oracle

From §6:
1. Load the compiled Narsese premises/program into **ONA**.
2. Run **20 inference cycles before the query**.
3. Ask the query and capture answer.
4. Convert returned frequency to category: >=0.50 → True; <=0.05 → False; intermediate → Uncertain.
5. **No answer** is also Uncertain.
6. Keep a case only if runtime label matches intended label.

This is not ordinary binary logical validity; the mapping uses ONA's returned frequency and a bounded execution schedule. A system using a different cycle budget/threshold may produce a different label without a logical contradiction.

## Pipeline and its limitations

`natural language -> FOL -> deterministic benchmark-subset compiler -> Narsese -> ONA -> label`

The paper proposes *Language-Structured Perception (LSP)*: learn to output structured, executable reasoning targets rather than fluent prose alone.

It defines an illustrative combined objective `L = L_text + λ L_exec` for token-based and execution-based supervision. Its released **Phi-2 LoRA adapter** is a simpler **direct three-label classifier**, not a demonstrated end-to-end executable Narsese generator. The paper itself makes that distinction (§7).

Compiler coverage is limited to certain atomic predicates, negation, conjunction/disjunction, implication, XOR and quantified rules; conversion can alter/strengthen semantics. Do not assume support for unrestricted FOL or all NAL layers.

## Measurement protocol for lance-graph

**Before implementing:** inspect current NARS engine/replay/CE64/planner/Quack and determine actual supported grammar. Do not add primitives to inflate coverage.

Keep independent outcome axes:
1. **Corpus availability:** how many cases loaded and schema-valid?
2. **Parse/compile coverage:** can each program be represented without changing semantics?
3. **Execution success:** cases actually run versus rejected/unsupported.
4. **Label parity:** among executed cases, agreement with ONA and gold.
5. **Numerical truth parity:** frequency/confidence delta where available, distinguishing original semantics from byte quantization.
6. **Provenance integrity:** no duplicate evidence roots across derivations.
7. **Replay determinism:** byte-identical results after snapshot reload, with same instruction/reading/recipe.
8. **Costs:** compute masks/folds, allocations, cold hydration, receipts, commit latency.

Never report "95% accuracy" if half the cases were unsupported and silently excluded. Present:
`
coverage = executable / total
conditional_accuracy = correct / executable
end_to_end_accuracy = correct / total
abstention_rate = explicit_unavailable / total
`

### Test splits

- Official held-out score: **200-case test**; avoid using it to tune semantics.
- Full 1,000 cases: diagnostic regression; mark **800 training cases**, not independent generalization evidence.
- Stratify by label, difficulty, grammar feature and inference depth.
- Fix ONA commit, CLI invocation, configuration, Narsese ordering and cycle counts. Store immutable run manifests.

### Critical falsifiers

- Syntax-valid but semantically strengthened translation: must flag semantic mismatch.
- Narsese equivalent by structure but different spelling: executable parity > string equality.
- One observation repeated across two paths: reject confidence inflation.
- Conflicting evidence: retain Uncertain instead of guess when oracle does.
- Query shifted before/after the 20 cycles: protocol drift detected.
- Unknown predicate/missing premise: no hallucinated inferred premise.
- Long chain with unsupported feature: count unsupported, never "passed."
- Outcome changes under independent permutation of semantically commutative input: investigate and report.
- CE64 epistemic mask change alone must not mint evidence or alter a recipe opcode.
- ONA crash/no output: report execution failure **separately** from legitimate no-answer Uncertain.

## Explicit non-claims

- 1,000 test examples do **not** cover NAL-1 through NAL-9 comprehensively.
- ONA passing the dataset does **not** prove the originally formulated FOL is preserved perfectly.
- Phi-2 LoRA predicting A/B/C does **not** demonstrate executable symbolic reasoning.
- A portable ALU fold equal to a Narsese subexpression is **not** full logical equivalence.
- Dataset verification was reported by authors; no fresh execution has occurred in this distillation.
