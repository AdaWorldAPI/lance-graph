# DAV-GSWT — Uncertainty Chooses the Next Observation

**Paper:** *DAV-GSWT: Diffusion-Active-View Sampling for Data-Efficient Gaussian Splatting Wang Tiles*  
**Authors:** Rong Fu, Jiekai Wu, Yang Li, Xiaowen Ma, Wangyu Wu, Simon Fong  
**arXiv:** 2602.15355v6  
**Source:** https://arxiv.org/abs/2602.15355  
**PDF:** https://arxiv.org/pdf/2602.15355  
**Version checked:** v6, 2026-08-26

## Punchline

> **Uncertainty should not merely lower confidence. It should deterministically choose the next observation worth paying for.**

The transferable idea is not Gaussian splatting, Wang tiles, LPIPS, or diffusion.

It is the closed active-perception loop:

```text
current state
    |
    v
generate admissible alternatives
    |
    v
measure disagreement
    |
    v
rank candidate observations
    |
    v
spend a bounded observation budget
    |
    v
fold new evidence
    |
    v
repeat only where uncertainty remains
```

For lance-graph this is unusually close to the missing bridge between:

```text
59/60 epistemic pothole detection
        ->
which unknown should be measured next?
        ->
revision / Rubikon
        ->
replayable learning
```

The paper suggests a concrete answer:

> **Probe where admissible reconstructions disagree most, not where a single predictor merely reports low confidence.**

---

# What the paper actually establishes

## 1. Active acquisition is driven by ensemble disagreement

DAV-GSWT begins with a sparse reconstruction and a discrete candidate set of camera poses.

For each candidate pose `theta`, a diffusion prior is executed multiple times with stochastic attention dropout. The resulting latent samples are compared to estimate epistemic disagreement.

The operational loop is:

```text
for each candidate theta:
    sample M alternative latent reconstructions
    score disagreement u(theta)

select top-k theta by u(theta)
physically observe those poses
update the Gaussian field
repeat T times
```

The paper's default values are:

```text
M = 5 stochastic passes
k = 20 selected views per iteration
T = 3 active iterations
```

So the important object is not one confidence value emitted by one model.

It is:

```text
D(H1(x), H2(x), ..., HM(x))
```

where the `Hi` are alternative admissible reconstructions.

### Portable lesson

A system learns where to look by measuring **disagreement between plausible completions**.

That is much stronger than:

```text
prediction confidence < threshold
```

because a predictor can be confidently wrong.

---

## 2. Disagreement beats the single-forward baseline in the paper's ablation

The strongest reported uncertainty variant combines latent 2-Wasserstein ensemble disagreement with an LPIPS correction.

Reported Table 4 values:

| Uncertainty / selection path | PSNR | Seam-LPIPS | Uncertainty time |
|---|---:|---:|---:|
| Full ensemble W2 + LPIPS | 29.41 +/- 0.08 | 0.031 +/- 0.002 | 1.8 +/- 0.1 s |
| W2 only | 29.12 +/- 0.09 | 0.034 +/- 0.003 | 1.3 +/- 0.1 s |
| Image gradient + LPIPS | 28.55 +/- 0.11 | 0.039 +/- 0.003 | 4.7 +/- 0.2 s |
| Single forward, no dropout | 27.03 +/- 0.15 | 0.051 +/- 0.004 | 0.3 +/- 0.0 s |
| Exhaustive 200-view baseline | 29.50 +/- 0.07 | 0.030 +/- 0.002 | n/a |

The transferable result is qualitative rather than metric-specific:

> **Independent plausible completions expose epistemic uncertainty that one deterministic completion hides.**

For lance-graph, W2 and LPIPS are not the primitive.

The primitive-shaped idea is:

```text
same evidence
+ several admissible replay paths
+ deterministic disagreement reduction
= probe priority
```

---

## 3. The next action is budgeted top-k, not unconstrained exploration

The paper does not chase every uncertain region.

It ranks candidates and spends a fixed acquisition budget.

```text
Theta* = top_k(theta by u(theta))
```

This maps cleanly to a bounded cognitive scheduler:

```text
candidate epistemic holes
        |
        v
score expected value of observing each
        |
        v
top-k under current budget
        |
        v
probe only those
```

That matters for lance-graph because "explore uncertainty" without a budget degenerates into global search.

The useful architecture is:

> **Uncertainty schedules work; it does not authorize unlimited work.**

---

## 4. Uncertainty also controls resource depth

DAV-GSWT reuses uncertainty after acquisition.

Tiles above an uncertainty threshold retain more cached orderings and prefetch deeper LODs.

Portable translation:

```text
high certainty
    -> stay compact
    -> shallow neighborhood
    -> fewer folds
    -> avoid materialization

high uncertainty
    -> hydrate more context
    -> inspect more neighboring structure
    -> spend more fold/revision budget
    -> materialize only when needed for replay
```

This is a useful model for **uncertainty-directed hydration**.

Knowledge does not need uniform representational thickness.

It can become locally thicker exactly where the substrate cannot yet close the Sudoku.

---

## 5. Boundaries can be chosen using uncertainty

After reconstruction, the paper performs uncertainty-adaptive graph-cut seam optimization.

The direct graphics details are domain-specific, but there is a portable systems idea:

> **Do not place a computational boundary where the unresolved semantic coupling is strongest.**

Candidate lance-graph translation:

```text
chunk / batch / materialization boundary
    prefers
low coupling + high agreement

keep together
    high coupling + high disagreement
```

This is only a hypothesis for lance-graph, not a storage contract.

It should be tested before allowing uncertainty to affect physical chunking.

# Harvest for lance-graph

## H1 — Epistemic pothole -> active probe

The strongest harvest is the transition:

```text
detect unresolved region
        ->
construct candidate observations
        ->
measure disagreement
        ->
rank probes
        ->
observe
        ->
revise
```

This turns a missing-link detector into a self-directed measurement loop.

A pothole is no longer only:

```text
"I do not know this."
```

It becomes:

```text
"These are the observations that would reduce the ambiguity most."
```

---

## H2 — Sharpen the 59/60 frontier into detect vs schedule

One possible interpretation, subject to the existing 0..63 contract:

```text
0..58   deterministic known transforms / folds / projections
59      expected closure or candidate completion exists
60      unresolved disagreement / closure failure
61..63  grade evidential / correlational / causal status after observation
```

DAV-GSWT suggests inserting an orchestration step between 60 and revision:

```text
60 unresolved
    |
    v
candidate probes
    |
    v
replay alternatives
    |
    v
disagreement rank
    |
    v
bounded observation
    |
    v
revision
    |
    v
61..63 may grade what the new evidence warrants
```

Important:

> **60 should not itself imply which hypothesis is true. It only identifies where current admissible completions fail to agree.**

---

## H3 — Probe should probably be orchestration, not a new fold primitive

Do not introduce a `PROBE` kernel merely because the paper has an active-view operator.

First try to express it as composition over existing machinery:

```text
candidate mask
    ->
bind / project
    ->
run admissible replay alternatives
    ->
fold disagreement
    ->
rank
    ->
top-k mask
```

Conceptually:

```text
PROBE = MASK + REPLAY + DISAGREEMENT_FOLD + TOPK
```

If those pieces already have stable ordinals, the correct addition may be only a **0..63 orchestration recipe** or R2IL microprogram.

Architectural guardrail:

> **Do not mint a new primitive until an existing Local/Via/fold composition has been falsified.**

The intelligence should live in when the existing operators are composed, not in another opaque kernel.

---

## H4 — Alternative replay paths become epistemic sensors

The paper injects stochasticity through dropout to obtain multiple plausible reconstructions.

lance-graph should not copy the stochastic mechanism blindly.

The deterministic analogue is stronger:

```text
H1 = ontology completion
H2 = statistical completion
H3 = causal / intervention-compatible completion
H4 = local Moore / neighborhood completion
H5 = prior revision path
```

All are replayable.

Then define:

```text
Disagreement(x)
    = D(H1(x), H2(x), ..., Hn(x))
```

The key distinction is:

```text
paper:
    stochastic samples from one generative prior

possible lance-graph version:
    deterministic samples from several admissible reasoning routes
```

That preserves replayability while harvesting the epistemic geometry.

---

## H5 — Probe priority should be value-of-information shaped

Raw disagreement is not automatically useful.

A highly ambiguous location may be irrelevant to the current objective.

So the substrate score should eventually distinguish:

```text
uncertainty
from
useful uncertainty
```

Candidate form:

```text
ProbeScore(x)
    = Disagreement(x)
    * Reachability(x)
    * GoalRelevance(x)
    * ExpectedRevisionImpact(x)
    / ObservationCost(x)
```

Do not canonize this equation.

The important contract is that all factors are explicit, bounded, quantized, and replayable.

This gives the Rubikon a natural budget interface:

```text
many epistemic potholes
        ->
rank expected information value
        ->
cross Rubikon only for top-k
```

---

## H6 — Hydration can follow uncertainty without changing truth

A valuable separation:

```text
truth/evidence state
        !=
amount of computation allocated to inspect it
```

Uncertainty may change:

- neighborhood depth;
- number of replay alternatives;
- cache retention;
- local fold budget;
- candidate expansion width;
- whether an intermediate must be materialized.

It must not silently change:

- observed facts;
- ontology identity;
- causal grade;
- evidence provenance.

This is a good substrate rule:

> **Uncertainty may schedule cognition. It may not manufacture evidence.**

# Candidate deterministic contract

A minimal conceptual contract could be:

```text
ProbePlan {
    snapshot_id
    candidate_population
    replay_program_ids[]
    disagreement_metric_id
    budget_k
    tie_break_contract
}
```

Execution:

```text
same snapshot
+ same candidates
+ same replay programs
+ same metric
+ same budget
+ same tie-break
--------------------------------
same selected probe ordinals
```

The selected probe set can then become an input to observation/revision.

No LLM should be required in the replay path.

An LLM may propose:

- candidate probe generators;
- a new replay program;
- a new disagreement recipe.

But those must become explicit validated artifacts before they can affect the committed probe ranking.

# Testables

## T1 — Missing-link recovery by disagreement

### Setup

1. Start from a graph / ontology region with known withheld facts or edges.
2. Remove a controlled subset.
3. Generate several admissible completions for every candidate hole.
4. Compute deterministic disagreement.
5. Rank holes by disagreement.

### Compare against

- random ranking;
- node degree;
- raw popcount;
- entropy alone;
- single-path confidence;
- distance to observed evidence.

### Pass shape

```text
Recall@k(disagreement)
    >
Recall@k(simple baselines)
```

for a useful range of small `k`.

### Falsifies

The claim that cross-path disagreement identifies epistemically valuable missing links.

---

## T2 — Probe budget curve

Evaluate:

```text
k = 1, 2, 4, 8, 16, ...
```

For each budget measure:

- repaired withheld facts;
- uncertainty reduction;
- revision quality;
- bytes read;
- folds executed;
- materializations;
- wall-clock time.

Required comparison:

```text
disagreement-ranked probes
vs
random probes
vs
entropy-ranked probes
vs
full scan
```

Desired shape:

> Small budgets should capture a disproportionate fraction of the benefit.

If performance scales only with brute-force coverage, the active-probe idea has failed.

---

## T3 — Replay determinism

### Contract

For a fixed snapshot:

```text
ProbePlan(snapshot) -> top-k
```

must be invariant under repeated execution.

Also permute:

- storage order;
- chunk order;
- hash iteration order;
- SIMD lane packing;
- candidate enumeration order.

Expected:

```text
same semantic candidate set
    ->
same scores
    ->
same top-k
    ->
same tie resolution
```

### Falsifies

Hidden scheduling intelligence leaking from physical layout or nondeterministic enumeration.

---

## T4 — Multi-route disagreement vs single-route confidence

Construct cases where one route is confidently wrong but other admissible routes disagree.

Expected:

```text
single path:
    low uncertainty

multi-route:
    high disagreement
```

After revealing ground truth, the disagreement ranking should identify more of these failures.

### Falsifies

The need for ensemble/replay disagreement if a single calibrated route performs equally well.

---

## T5 — Uncertainty-directed hydration

### Compare

```text
A: full hydration everywhere
B: fixed shallow hydration everywhere
C: uncertainty-directed hydration
```

Measure:

- final revision correctness;
- bytes touched;
- populations scanned;
- fold count;
- peak memory;
- materialized intermediates.

Desired result:

```text
quality(C) ~= quality(A)
cost(C) << cost(A)
quality(C) > quality(B)
```

### Falsifies

The idea that epistemic uncertainty is a useful scheduler for representational depth.

---

## T6 — Resolve-and-collapse

A correct probe policy should not keep rediscovering the same pothole after decisive evidence arrives.

Lifecycle:

```text
high disagreement
    ->
probe
    ->
new evidence
    ->
revision
    ->
disagreement collapses
    ->
budget moves elsewhere
```

Test:

After inserting the withheld ground-truth edge/fact, the candidate's probe rank should fall sharply unless genuinely independent ambiguity remains.

### Falsifies

Uncertainty metrics that measure structural complexity rather than reducible ignorance.

---

## T7 — Irrelevant ambiguity must not steal the budget

Create two regions:

```text
A = highly ambiguous but irrelevant to current objective
B = moderately ambiguous but blocks current inference
```

A raw-disagreement scheduler may choose A.

A useful active-reasoning scheduler should choose B when goal/revision impact is part of the contract.

### Falsifies

Using disagreement alone as a universal next-action policy.

---

## T8 — Top-k tie contract

Create many candidates with exactly equal quantized disagreement.

Verify that selection is determined by an explicit stable tie rule, for example semantic ordinal or content-addressed identity, never incidental iteration order.

Expected:

```text
equal scores + same identities
    ->
same top-k across replay
```

This is required if probe selection is ever part of a replayable 0..63 recipe.

# Paper claims not to import as substrate truth

The architectural idea is stronger than several theoretical claims in the appendix.

## C1 — The submodularity / 1 - 1/e argument is not established by Eq. 10

The appendix defines the selected-view objective as:

```text
argmax over |V| = k of sum_{v in V} U(v)
```

As written, that is an additive set score.

The text then claims submodularity, diminishing marginal utility, monotonic global-error decrease, and a `1 - 1/e` approximation guarantee without deriving the needed relation between view interactions, the update dynamics, and the objective.

Do not harvest the guarantee.

Harvest only:

```text
bounded greedy ranking is a useful executable policy
```

and falsify it empirically against alternatives.

---

## C2 — The claimed C1 LOD boundary continuity is suspect

The appendix uses a clamped linear blend and says sufficiently large `Delta` gives C1 continuity at the clamp boundaries.

A clamped linear ramp is C0 continuous, but its derivative changes from zero outside the ramp to a nonzero constant inside it.

Changing the width changes the slope magnitude; it does not remove the derivative discontinuity for finite `Delta`.

Do not treat the appendix claim as a mathematical template.

---

## C3 — "One order of magnitude fewer views" is not supported by the displayed budgets

The paper's standard active loop uses:

```text
k = 20
T = 3
=> 60 active captures
```

and starts from 8 initial views.

Figure 7 marks 60 shots and compares against an exhaustive 100-view line.

Table 4 also reports an exhaustive 200-view baseline.

Those ratios are useful data-efficiency gains, but not roughly 10x:

```text
100 / 60  ~= 1.67x
200 / 60  ~= 3.33x
200 / 68  ~= 2.94x   if initial views are counted
```

So use the measured budget curve, not the prose superlative.

---

## C4 — Figure 3 is not an independent final-error validation

Figure 3 visualizes intermediate error relative to the **final reconstruction**.

That is useful for showing convergence toward the method's own terminal state.

It is not equivalent to error against independent ground truth.

Do not use it to justify correctness of revision.

For lance-graph the analogue must be:

```text
revision trajectory
    evaluated against
withheld / independently revealed evidence
```

not merely convergence to its own eventual fixed point.

---

## C5 — Generated alternatives are hypotheses, not evidence

The paper uses a diffusion prior to hallucinate plausible views and then uses physical acquisition to resolve them.

That separation is essential.

For lance-graph:

```text
generated completion
    = hypothesis

observed / sourced fact
    = evidence
```

No amount of agreement among generated completions should silently promote a hypothesis into observed truth.

This is especially important near 61..63.

---

# Smallest implementation experiment

Do not begin with a new crate or a new 0..63 primitive.

Start with a synthetic falsifier next to the existing revision / frontier machinery:

```text
1. create a known graph
2. hide a small set of edges
3. expose 3-5 deterministic completion routes
4. compute per-hole disagreement
5. top-k rank holes
6. reveal the hidden facts only for selected holes
7. run revision
8. compare against random / entropy / degree baselines
```

The first useful artifact is probably a benchmark/test harness, not production architecture.

Suggested output per replay:

```text
candidate_id
route_outputs
disagreement_score
rank
selected
observation_cost
revealed_truth
revision_delta
post_revision_disagreement
```

That gives enough evidence to decide whether this deserves a stable orchestration recipe.

---

# Decision rule

Adopt the idea only if all three are true:

```text
1. disagreement predicts useful missing observations better than simple baselines
2. top-k probing saves meaningful work versus broad hydration
3. probe selection is bit-for-bit replayable from the same snapshot
```

Otherwise keep 59/60 as detection only.

If it passes:

> **59/60 stop being merely the place where the substrate notices a hole. They become the doorway through which the substrate chooses the cheapest observation that can close it.**

That is the real harvest from DAV-GSWT.
