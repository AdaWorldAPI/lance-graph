# Chordal codes: eliminate in an order that avoids fill-in

**Source:** Yulin Chen, Laigang Guo, Tong Li, Mingyang Zhu, *Chordal Codes: Code Construction and Efficient Gaussian-Elimination Decoding*, [arXiv:2610.17934v1](https://arxiv.org/abs/2610.17934), [HTML](https://arxiv.org/html/2610.17934v1); submitted 2026-10-13. §§II-A, III, IV.  
**Research status (2026-10-21):** Primary-source excerpt; proposed applications below are **hypotheses**, not demonstrated by the paper for QR256.

## Source-grounded excerpt

Maximum-likelihood decoding over an erasure channel becomes a finite-field linear system involving a column-submatrix of the parity-check matrix. Gaussian elimination may introduce **fill-in**, extra nonzeros that cost memory and work. The paper defines chordal codes whose **primal graph** is chordal and analyzes a **perfect elimination ordering** (PEO). Erasure-induced column submatrices inherit the relevant chordal primal-graph property. The advantage concerns that *structured family*, not an assertion that any arbitrary graph has a zero-fill order.

Here the primal graph has one vertex per matrix **column**, with an edge whenever two columns co-occur as nonzero entries of some matrix row. It is not automatically the directed relationship graph of an ontology.

## Hypothetical transfer to lance-graph

The promising operation is **plan ordering before elimination**, not a new math backend. For a set of relational variables and shared subexpressions, build a variable-interaction graph; if a proven legal decomposition exists, explore a low-fill elimination order. Preserve the precise operation algebra (GF(2), Boolean OR/AND, or bag counts) and its equivalence obligations. Plan-level fill-in means new intermediate dependencies/materialized planes; it is an **analogy** until measured.

A QR256 state has only 8 KiB of packed truth bits, but an unfortunate elimination order could still create large intermediate products, explanation traces, or off-focus edges.

## Falsifiers / test path C

- **C1:** Construct chordal and nonchordal **primal** graphs from typed linear equations. Compute a PEO with an independent recognition oracle; compare peak fill-in, rank, correctness and row-XOR counts against natural order, reversed order and greedy min-fill. A nonchordal input must never be labeled no-fill.
- **C2:** For acyclic star/chain relalg bodies, compare elimination orders on **identical** set semantics, including a 256-method/256-slot focus. Measure intermediate planes and DAG nodes, not just number of rewrites.
- **C3:** A cyclic triangle where semijoins do not filter anything must remain a counterexample: identical pairwise domain projections do not guarantee the whole join is nonempty (cf. [#1587](https://github.com/AdaWorldAPI/lance-graph/pull/1587)).
- **C4:** Hubs, power-law degree, reordered row ordinals and external focus escapes. If a PEO-based claim misses an escape or increases total time on a sparse case, stop promotion.
- **Silence twin:** A coordinate permutation that only changes presentation must not create new facts or writeback deltas.

**Verdict:** Research as a *cold optimizer heuristic*; no claim that chordal erasure-code complexity transfers wholesale to Datalog.
