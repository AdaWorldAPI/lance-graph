# D-EPI-COT C3c — learned ordering of scent leads

Status: TEST-PINNED on fixture worlds. Code:
`crates/lance-graph-planner/src/nars/scent_learn.rs`. Builds on C3b (`scent`).

## Question

C3b ranks candidate mediators by status, then by uncertainty. When several
leads tie on both, the order falls back to mediator id, which carries no
information. Can past investigation outcomes order those ties better?

## Answer: `nars::scent_learn::ScentLearner`

- A linear score over five lead features: bias, anchor confidence, anchor
  frequency, uncertainty, and the number of links with evidence.
- The learner reorders leads **within** a status group. It never moves a lead
  across groups, so a contested lead stays ahead of a settled one (PZ8).
- After each investigation it updates on the signed residual
  `target − prediction`. The target is ±127: hydrated is +, refuted is −.
- Its output is an order. It holds no ledger or edge and writes neither. A
  prediction is never recorded as an observation.

## Numerics: no runtime rounding, no float roundtrip

| piece | where | contract |
|---|---|---|
| weights, deltas, steps | `ndarray::hpc::codec9::EpiLane9` | `NEVER_TOUCHED` (P=0, M=0) = feature never seen; a touched zero is `+0` |
| delta | integer, in code space | `M = |r|·x / 255` truncated (odd, deterministic); sign from `r` |
| zero rule | bit masks | `P = present AND (positive OR M == 0)`: −0.49 → −0 → +0, never "never touched" |
| learning rate | `ndarray::simd::lut9` | a plain lookup of an odd table; same zero rule on its output |
| weights | integer add, saturate to ±255 | written back as an SM9 codeword, no re-encode |
| rate table | built once, offline | TFLM `LUTPopulateInt8`: `x·η`, `TfLiteRound` (ties away), saturate |

The only rounding is when the rate table is built, which happens once per
spec. The hot path is integer arithmetic, two bit masks and one `lut9` call.
An earlier draft encoded each delta and weight through `f32` and
`Codec9::encode_touched`. That was a runtime float roundtrip and is gone.

**TFLM reference.** `data/tflm_lut_step_golden.txt` was generated by
`oracles/tflm_lut_step_oracle.cc`, compiled against AdaWorldAPI/tflite-micro
`5f64e4a` (`tensorflow/lite/micro/kernels/internal/common.h`, `LUTPopulate`).

- It covers four rates (1/4, 1/2, 3/4, 1) over all 256 int8 codes.
- The SM9 table matches TFLM on every code: `table[v]` for `v ≥ 0` and
  `−table[−v]` for `v < 0`. Ties-away rounding of `x·η` is odd, which is why
  one magnitude table covers both signs.
- Magnitudes 129..=255 use the same formula but have no int8 TFLM counterpart.

In-tree, ndarray's requantization chain (`simd_fixedpoint`) is byte-parity
tested against TFLM. `lut9` itself is tested against a scalar oracle, and
Codec9's never-touched code has no TFLM counterpart (TFLM reserves no int8
code). The TFLM claim here is about this rate table only.

**Spec binding (PZ7).** A prepared table carries `ModelSpec`, which is the
feature schema, the feature scale (255 = 1.0) and the rate. A learner refuses a table
built for a different spec. The spec lives in memory only. It is not a
generation store and not EXO-152's PZL-4/G1 binding.

10 disables, each red. The zero-rule disable stayed green twice before its
test bound it. The first time, no fixture had a delta that rounds to zero.
The second time, the fixture's residual was positive, so the sign set P on
its own. The test now uses a negative residual, which is the −0.49 case.

## Measured

PZ5 trains on 40 worlds of one shape: 3 decoys, the known link `A → B`. It
tests on 600 held-out worlds of another shape: 7 decoys, the known link
`B → Y`, disjoint seeds. The table shows mean investigations to hydrate the
true mediator. The standard error is about 0.1.

| policy | informative fixture | uninformative twin |
|---|---|---|
| learned | 1.00 | 4.59 |
| scent (id order) | 4.51 | 4.51 |
| round-robin | 4.55 | 4.55 |
| random | 4.47 | 4.47 |

On 60 held-out worlds, the uninformative twin first read 3.77 against
random's 4.73. On 600 worlds the gap is gone, and the learned weights stay
near zero (1, 2, −3, 1, 3), so the 3.77 was sampling noise. The test now uses
600 worlds with a 0.5 bound.

## NSL research plans (AdaWorldAPI/neural-structured-learning #1–#8)

The NSL plans are documentation-only research proposals dated 2026-10-25,
before `lut9` merged. None of them mention `lut9`. Where they apply here:

- **05a, certified pair LUT:** tables are generated and certified offline, and
  a query is a plain array lookup with no runtime rounding or libm call. C3c
  follows that. Its rate table has rational ties (for example 2·¼ = 0.5) that
  05a would call undecidable without a rule. Here the rule is TFLM's ties
  away from zero, and the table is pinned against TFLM.
- **Scratchpad §5:** keep the TFLM rounding contract (ndarray #375) and the
  Codec8/Codec9 code spaces. C3c adds no codec and no rounding mode.
- **H1 (graph focus, 01/01a):** NSL's graph regularization uses structure as
  a training signal. C3c's learner is a different signal: investigation
  outcomes. A graph-regularized learner, where leads that share an anchor
  source are pulled toward similar scores, is a possible later step. It is
  not built here.
- **`lance-graph-nsl`:** the NSL scratchpad gates any lance-graph
  implementation on a frozen NSL oracle (H7) and the G01–G12 neighbor
  fixtures (H1). Neither exists yet, so this PR adds no NSL crate.

## What this does not show

- **The informative fixture is separable.** True mediators have anchor
  confidence 0.8–0.95 and decoys 0.15–0.45, so 1.00 measures that the learner
  finds a separating feature. It does not measure performance on realistic,
  overlapping evidence.
- **One fixture family, one host.** HIRO and ERP-consumer outcomes are not used yet.
- **No discrimination target yet.** The target is "this lead hydrated".
  C3c-plan §5 asks for "this ablation discriminated between competing
  intermediates", which needs the ledger's `sensitivity` as the label. That
  is the next step.
- **The score is a ranking.** No calibrated probability is claimed.
- **Bits 50..52 are untouched.**
