## P0: mathematical premise soundness before expanding beyond E1

**Observed:** `Problem { premises: Vec<Eq> }` is public. `encode::setup` indiscriminately `union`s every equation, while `oracle::solve` builds a forward `BTreeMap` and silently skips subsequent definitions of the same `lhs`. Neither `ReplayCapsule::certify` nor `Catalogue::promote` currently validates duplicate/conflicting definitions, attempts to define the freely supplied target, or cycles in a generalized input graph.

**Concrete counterexample to test (NOT claimed executed):**
```text
goal=z; target=c; premises=[ z=2*c, z=3*c ]; supplied c=7
```
These premises conflict for nonzero c. egglog considers both asserted equalities true; the i128 oracle may retain the first equation and ignore the second. A matching sample therefore need not establish that the full equation set is jointly valid for every runtime input. This is **not a flaw in egglog**: it is a missing caller contract for treating equations as universally valid definitions.

**Minimal next code change, separate owned PR:** validate that `target_var` is a free parameter, each `lhs` has a unique definition, reachable definitions are acyclic and every dependency needed by the goal resolves to the target or refuses. Reject conflicts **before `union` or promotion**. Add adversarial tests for conflicting duplicate heads, two contradictory paths, `c=2c`, cycles, disconnected premises and benign duplicate equations. Independently check every equation against generated input assignments, including negative and boundary values, rather than trusting the first path. Only then consider reusable arbitrary equation DAGs. Keep #1693's valid E1 behavior unchanged.

## P1: distinguish mathematical, compiled, binding and execution identities

The following are different and must not be collapsed into one `SemanticKey` or one vague `certified` flag:

1. **Math identity**: normalized statement + assumptions + typed domain (Exact / Checked / Wrapping / IEEE, Boolean set / SQL K3+validity / Bag+Distinct) + admitted law IDs and rule versions. A historical attribution is *not* a mathematical assumption.
2. **Compiler identity**: extracted term, R2IL step list, lowering and target/ABI versions, cost objective, egglog engine/checker version, and optional proof DAG/checker receipt. A rendered proof string alone is not a durable independent proof.
3. **Binding identity**: dataset and source snapshot(s), focus, source↔local codebook mapping, typed coordinate domain and attested generations. `BindingWitness { source_generation, scope, coordinate_generation }` is currently caller-supplied lab metadata. Two unrelated sources with the same numeric generation values still must not alias.
4. **Execution identity**: actual inputs, BEFORE/AFTER or independent output oracle, error/refusal codes, physical reads and separate durable commit acknowledgment. `ReplayCapsule::execute` is **not** a write or a source-attested replay.
5. **Historical identity**: edition/source locator, transcription normalization and uncertainty; can be reviewed independently from mathematical formalization or proof.

Proposed reference-only join shape for EXO-98 / D-TGB-4 (no writer integration here):
```text
TheoremRef(math_id, source_edition?, assumptions, domain)
  -> LawProofRef(proof_id, checker_version, typed_law_ids)
  -> CompiledPatternRef(r2il_steps_digest, target_abi, compiler_revision)
  -> BindingRef(dataset, snapshot, focus, coordinate_codebook, generations)
  -> ReplayRef(inputs, result, comparison, error, proof_receipt)
  -> CommitRef(optional, real coalesced cycle + durable store witness)
```
**Never** mistake an equality proof, a call-success result, an unsigned Fold receipt, or `CandidateDirty` for a durable acknowledged commit. Thought-Git's current `Receipt`, `BaseRef`, `ProgramId`, metadata seal and `CommitWitness` already express **different** lifecycle concepts. Link by immutable IDs/references and admission fences rather than putting egglog into Thought-Git's hot cycle.

## P1: honest fallback and measured economics

`Catalogue::promote` checks a caller-provided `CostEvidence` where `(baseline_ns-candidate_ns)*expected_reuse > compile_and_certify_ns`. This is a good *lab policy formula* but not self-attesting cost evidence. A false positive can be generated by invented inputs; even honest averages need variance and workload shape.

**Measure independently**: cold egglog+proof, cold independent oracle/checker, catalogue lookup, binding/attestation, first execution, steady R2IL path, baseline path, runtime refusal/fallback, output materialization and retained proof bytes. Include instruction-cache and e-graph costs for high-width extraction. A cache hit with identical goal and coefficients but wrong source snapshot is a red failure, irrespective of the saved nanoseconds.

**Required E2 sample**: 256 distinct rules × 4,096 pinned contexts (1,048,576 requested uses), plus deliberately *nonsharing* control. Compare direct relalg normalization/CSE and existing R2IL procedures first; optionally add relational e-matching, babble abstraction reuse and effect-safe extraction **only if those baselines show a real gap**. Quantify amortized net savings and refused/witness-invalidated work. Cold compile cannot be hidden by `CLAUDE.md`'s reporting-budget language.
