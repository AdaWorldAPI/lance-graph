DuckDB is the semantic oracle for this suite. Expected values in cases.tsv
are NEVER hand-edited — they are always regenerated by running oracle.py.

To regenerate the fixture + expected values after a change to fixture.rs
or cases.tsv's SQL:

  cargo test -p lance-graph-quack --test duckdb_differential \
      write_fixture -- --ignored
  <venv-with-duckdb>/bin/python tests/duckdb/oracle.py

Encoding: bare scalar -> decimal string; EXISTS -> "0"/"1"; grouped result
-> "k1:v1;k2:v2;..." sorted by key; rid projection -> sorted comma list.
Both oracle.py and duckdb_differential.rs implement this encoding
independently; they must agree, which is what the suite checks.
