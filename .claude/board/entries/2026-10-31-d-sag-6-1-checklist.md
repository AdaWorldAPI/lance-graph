## 2. Pinned fixture — what each tool witnessed

The fixture `sag_fixture` (`src/lib.rs`) contains:
- `count_below`: pure filter-count;
- `count_generic` and `count_dyn`: the same with a trait predicate, generic and `dyn`;
- `count_with_tally`: a closure that writes captured state;
- `count_div`: a predicate that can panic;
- `popcount_mask` and `mask_below`: the mask form;
- `a::helper` and `b::helper`: same-named functions;
- a `macro_rules!` function `twice`;
- `#[derive(Clone, Debug, PartialEq)]`.

**Charon** (via `tools/llbc_calls.py`). Each closure is its own function (`…::Impl::call_mut`).

| Function | Calls | Writes through deref | `Assert` |
|---|---|---|---|
| `count_below` closure | none | 0 | 0 |
| `count_generic` closure | `trait` (generic-clause trait method) | 0 | 0 |
| `count_dyn` closure | `dynamic` (vtable) | 0 | 0 |
| `count_with_tally` closure | none | **1** (`*seen += 1`) | 1 (overflow check) |
| `count_div` closure | none | 0 | **1** (division by zero) |
| `popcount_mask` closure | static `count_ones` | 0 | 0 |
| `use_helpers` | static `a::helper`, static `b::helper` | 0 | 1 |
| `call_twice` | static `twice` | 0 | 0 |

The three derived impls (`clone`, `fmt`, `eq`) are present in Charon's output.

**rust-analyzer** (`DUMP=1`):
- The two `helper`s are distinct symbols, each with its own definition and one reference.
- `twice`, generated by `macro_rules!`, is indexed.
- Both `p.test(x)` calls resolve to the trait method declaration (3 references: declaration plus the two calls). The impl methods have only their definitions.
- The derived impls are absent: proc macros are not expanded without the build-script run.
- MIR lowered for 17/17 bodies.

So the two tools disagree on coverage exactly where expected: derives present in Charon and absent in rust-analyzer. Coverage must therefore be recorded per source, not assumed.

> **Correction (D-SAG-6-2, same day):** the cause given above is wrong.
> - `Clone`, `Debug` and `PartialEq` are built-in derives, and rust-analyzer expands them without the proc-macro server. `goto_implementation` on `Below` returns 4 impls (`Pred` plus the three derives), against 1 for `Even`.
> - They are missing from `StaticIndex` because it indexes tokens written in the source, and a derived impl has none.
> - The gap is in the index used, not in macro expansion. See [D-SAG-6-2-LAB](2026-10-31-d-sag-6-2-lab-projection.md) §1.

## 3. Call site, possible callee, observed call

- **Call site:** both tools witness it.
- **Resolved static callee:** Charon `Regular`/`Fun`, or a rust-analyzer reference to a free function.
- **Possible callee:**
  - a generic-clause trait call (Charon `trait`) can reach any impl in scope at instantiation;
  - a `dyn` call (Charon `dynamic`) can reach any impl, including ones outside the crate;
  - rust-analyzer references the trait declaration, never an impl.
  - Neither tool asserts a confirmed callee for these, and the projection must not either.
- **Observed call:** neither tool records one. It needs execution evidence (a trace, or a test that runs the path). Status MISSING, and it must stay a separate relation.

**The law test's first version was vacuous.** It drew values from all of `u32`, so `x == t` never occurred, and a `<` → `<=` slip in `mask_below` stayed green. Drawing from 0..16 makes ties occur. With that, the same slip fails the test, and the restored code passes.

## 5. Source edit path

rust-analyzer's `rename`, `structural_search_replace` and `assists_with_fixes` return a `SourceChange`: per-file text edits that leave formatting and comments untouched and are not applied. That makes a proposal inert by construction (F13).

`syn`/`quote` regeneration is not justified for edits: it reprints whole items and loses comments and layout.

MLIR is MISSING and remains an optional export, never a source of truth.

## 6. Smallest read-only adapter

The smallest step is to grow the existing lab crate `crates/sag-ra-probe` (excluded, nothing depends on it) into a two-source projection. No new store, no new registry:

1. **Inputs:**
   - rust-analyzer in-process: symbols, spans, references;
   - Charon LLBC out-of-process: bodies, calls, effects.

   Both are recorded with toolchain, revision, profile and coverage.
2. **Identity:** source path + revision + feature set + profile + source digest. Positional ids from either tool never act as identity (F01, F11).
3. **Rows:** a 4+12 facet key per symbol and operation under a provisional lab classid, and one edge row per relation. These are the layout already recorded in [the codegraph map](2026-10-30-d-tract-codegraph-address-map.md) §7b.
4. **Binding target:** an admitted method binds through `lance-graph-dt64`'s existing `Effect` / `MethodBinding` / `AlgebraRef`. `Effect` already carries an ordered argument list and a target field, which is the order-preserving shape a code operation needs. No new binding type.

**Math: PARK.** The fixture's law needs no new algebra. Its mask form is mask-risc's existing popcount fold, so admitting it is an alias, not a new word.
