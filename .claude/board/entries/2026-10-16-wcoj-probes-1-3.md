## P-1 result: galloping is a middle band, not a win everywhere

Comparisons per seek over N = 2²⁰ keys (counted, not timed):

| N/m | galloping | fresh binary search | linear step |
|---:|---:|---:|---:|
| 2 | 4.00 | 21.00 | 3.00 |
| 16 | 11.00 | 21.00 | 17.00 |
| 256 | 19.00 | 21.00 | 256.94 |
| 4,096 | 26.90 | 21.00 | 4,081 |
| 65,536 | 32.88 | 21.00 | 61,441 |

- The bound holds with constant 4: `m·(2·log₂(N/m) + 4)`. The pre-registered
  constant was 2, and N/m = 4,096 measured 26.9 against 26, from the ceilings
  in the bracket search and the cursor check. The slope matches; the test pins
  the measured constant.
- The pre-registered kill ("no speedup over a fresh `partition_point` at
  N/m ≥ 10³") was stated the wrong way round. Galloping beats a fresh binary
  search only for N/m below about 1,000, and beats a linear step only above
  about 16. A leapfrog seek therefore wants a step-then-gallop-then-search
  hybrid; that is a design input for D-ASM-11, not a kill.
- Timed below; see the next section.

## P-1 timed on v4: the hybrid seek

`examples/seek_probe.rs`, `avx512f=true`, ns per seek. Each row is the second of
two runs; the other run agrees within about 20%.

| N | N/m | gallop | fresh search | linear | hybrid |
|---|---:|---:|---:|---:|---:|
| 2²⁰ | 2 | 3.6 | 22.8 | 2.3 | 1.7 |
| 2²⁰ | 16 | 21.8 | 26.5 | 11.5 | 8.0 |
| 2²⁰ | 256 | 62.9 | 102.4 | 167.2 | 63.3 |
| 2²⁰ | 4,096 | 159.8 | 100.4 | 2,624 | 112.2 |
| 2²⁰ | 65,536 | 102.1 | 52.7 | — | 49.4 |
| 2²⁴ | 2 | 5.3 | 53.3 | 3.4 | 3.6 |
| 2²⁴ | 16 | 41.0 | 53.6 | 24.7 | 19.6 |
| 2²⁴ | 256 | 170.4 | 260.3 | 336.8 | 151.0 |
| 2²⁴ | 4,096 | 258.4 | 246.8 | 4,605 | 291.5 |
| 2²⁴ | 65,536 | 526.9 | 271.6 | — | 261.1 |

`seek_partition_point(keys, from, gap_hint, pred)` routes as follows:
- a gap of at most 16: linear step;
- `gap² ≥ N`: a whole-lane binary search;
- otherwise: gallop.

It is fastest or within noise of the fastest at every ratio. Two findings
moved the thresholds away from the comparison counts:
- **A linear step beats galloping up to a gap of about 16 in time**, although
  galloping makes fewer comparisons there (11 vs 17). Branch prediction
  reverses the count.
- **A fresh search of the whole lane beats a search of the remaining tail by
  about 2×.** The first hybrid searched the tail. A whole-lane search revisits
  the same top midpoints, which stay in cache; a tail search does not. The
  whole-lane search gives the same answer, because `pred` holds below the
  cursor.

The test `hybrid_seek_routes_by_gap_hint` pins the routing. Disabling the
whole-lane branch turns it red.

## P-7 result: expressible, not at the bound

mask-risc compares a lane with a constant, never with another lane. The exact
triangle mask needs `s_dst[rb[a]] == tc[a]`, so today it can only be written as
a disjunction over the value domain, `∨_v (EqU32Via(rb, s_dst, v) ∧ tc == v)`.
That is correct, but the program grows by about 4 ops per value (66 ops at
|D| = 16, 1,026 at |D| = 256), so the row work is Θ(rows · |D|). This misses
N^1.5 once |D| > √N. Two things are missing: a lane-to-lane comparison through
the fk, and, for non-functional relations, a sorted-run intersection. The
functional-lane layout cannot represent the n:m case at all. Rule 25 is met: the
insufficiency is shown, so one fused op may be proposed. It is not built here.

## Bind DTO synergies (for SAP and others)

The bind surface is quack's `Binder` trait (`lance-graph-quack/src/bind.rs:92`):
`table`, `live`, `field → BoundField{col, kind, validity}`, `code`. It never
mints. Implementers today:
- `lance-graph-sap::CatsBinder`;
- `lance-graph-dir-sim`;
- `lance-graph-report` (its test);
- `lance-graph-glove-parity`.

- **D-ASM-1/1b should implement `Binder`, not add a binder.** Atom and type
  names resolve through `code`, and the label codebook sits behind it. The
  content address (D-ASM-12) is issued at ingest; binding never mints it,
  which matches the trait's contract.
- **Keep codebook storage separate.** CATS codes are batch-local (the batch
  dictionary). Atom addresses must be stable across batches. Share the trait,
  not the dictionary.
- **SAP optional fields.** `CatsBinder::field` refuses optional fields because
  CATS stores NULL as a sentinel. `BoundField.validity` and the three-valued
  `Draft::bind` already exist (`bind.rs:77-89`). A validity plane built at
  `CatsBatch::bind` would unlock them. This is a candidate, not built.
- **Joins do not bind yet.** `Draft` is one table (`bind.rs:195`), so a
  multi-atom body (D-ASM-11, or SAP CATS ⋈ employee assignment) has no bind
  path. This gap is shared by MeTTa bodies and SAP joins.
- **SAP aggregates across n:m joins need the X17 oracle.** For example, hours
  per cost center through an n:m assignment. A mask cannot carry the count, so
  this is the fan-out undercount D-ASM-3 names.
- **`Registrar` has no production implementation** (`bind.rs` module doc).
  An atomspace-lance type registration would be the first real one; it is not
  proposed here.
