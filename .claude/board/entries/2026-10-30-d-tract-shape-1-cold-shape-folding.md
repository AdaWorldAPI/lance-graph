# D-TRACT-SHAPE-1 — cold shape folding and ON × WHEN × DO admission of the shape ops

**Date 2026-10-30 · Status LAB PROBE · Plan [`d-tract-harvest-0-native-algebra-bridge-v1.md`](../../plans/d-tract-harvest-0-native-algebra-bridge-v1.md) §0.2 · Crate `crates/tract-harvest-probe`**

Every value is classed Const / Shape / Symbolic / Data. A node folds at resolution only through its own registration (WHEN TRUE, then its DO) and only when invariant under the source and the resolved input facts; a run with other input dims is refused. Registry v2 adds Shape, Gather (int64 data), Unsqueeze, Concat, Reshape, Cast i64→i64 and Erf (`vserf`); scalar-Y Where uses `blend_i32_scalar`.

A Tract fact is admitted only from the value's source-producer outlet (a matching label is not authority): typed 1,988 of 2,546 admitted, 558 rejected; inference 0 rejected. Tract `TDim` is read as int64. A Tract panic (out-of-range constant Gather index) is a frontend refusal.

**Jina coverage [WHEN-true, not-true, unregistered], pinned [1,10]:** 4,146 / 0 / 3,474 → **6,404 / 56 / 1,160**; 4,440 nodes fold in 7.3 ms, 1,972 folded values retained (~20 KB). The remaining shape blockers are int64 arithmetic (Mul 115, ConstantOfShape 59, Equal 58, Where 58, Div 56, …), which no ndarray word covers.

Fixtures (ORT 1.29.0 `ORT_DISABLE_ALL`): shape chain bit-exact; Erf ≤ 2 ULP vs ORT and f64 over 4,115 points. 40 tests; 9 disable runs red.

**Bind-store consumer (plan §0.6):** `bind::route` (position → classid, sparse, versioned) and `bind::resolve` (classid → registration, failed link named) split `Registry::lookup` into the DR64 route and the DT64 bind store with no registry change; classids are unique. The one-tile `OnnxGraph` refuses Jina's 7,620 nodes, so the binder reads facts, not the tile. 2 more disable runs red. OPEN: DT64 crate, DR route table and tile coordinates are other owners'.

**CORRECTION (plan §0.7):** a classid is a codebook lens, not a codebook item. The per-op-signature classids (0x0F01…0x0F82) in every paragraph above are superseded: registry v6 reads the ONNX op codebook through one lens (`ONNX_LENS`) and addresses each signature as `MethodKey { lens, ordinal }`, ordinal = position. Bind-store routes carry the key; `resolve` fails as Route / Lens / Item. Results unchanged; 2 disable runs red.

**Field view (plan §0.8):** registry v7 follows ClassView + `WideFieldMask` (the Redmine ERB field-view pattern). `methods` are lens-agnostic algebra addresses, one DO body each; `regs` are the lens's fields, labelling one address each with a signature and its WHEN; `exposed` is the lens's `WideFieldMask`. A field outside the mask neither matches nor resolves, and `Registry::revision()` (version + exposed positions) keys the frame and the routes. 48 fields share fewer addresses. Jina unchanged; 4 disable runs red.

**DR64 global to local (plan §0.9):** `OnnxGraph::build` no longer refuses graphs beyond one tile. Positions map to (tile, local bit); `on`/`do_`/`dep` are `Tiled` relations composed tile by tile with the one DR64 kernel; the only ceiling is 65,536 positions. Full Jina (7,620 nodes, 7,939 values) builds, its tiled `dep` (391 tiles) equals the source edges, and it schedules. The registry's exposure mask is blocked by 256, so the codebook reaches 65,536 fields. 3 disable runs red.

Fixture `jina_ops` matches ORT (exact ops bit for bit; Sigmoid 1 ULP, Softmax 2 ULP from f64). Jina at [1, 10]: 7,620 / 0 / 0. 10 disable runs red.
