- **Single highest-value replacement:** `cam.rs`'s `AdcMetric::Cosine` path (`AdcMetric::cell` L260-271 feeding `DistanceTableProvider::distance`/`distance_batch` L172,175,344-354). It is the one site in this crate where (a) the computation is genuinely cosine, (b) it runs on the documented hot path (`CamPqScanOp`, per-candidate, described elsewhere in this crate as needing to reject 99% of candidates at billion-scale), and (c) the crate's own comments already frame it as "the cosine-replacement path" without actually having replaced it — the table stays `f32` end-to-end instead of becoming a quantized/integer palette256 LUT read. A `Distance`-trait impl for the CAM carrier exists (`impl Distance for [u8;6]`) but is explicitly documented as an L1 stand-in, not this ADC's real per-centroid distance — so closing this gap means either (i) quantizing `ScalarAdc`'s tables to an integer form the `Distance` trait can serve, or (ii) documenting why the ADC path is a sanctioned float exception to "no float ever in reasoning paths."
